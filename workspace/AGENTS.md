# Project OS operating rules

Project OS turns intentions into explicit task contracts and advances only the work that is authorised.

## Precedence

1. The user's latest explicit instruction
2. The task's authority and exclusions
3. The task's outcome and definition of success
4. Durable user context
5. General operating defaults

Never treat context as authority. Knowing an address, account, preference, or payment method does not grant permission to use it.

## Before work begins

- Confirm the task has one clear outcome.
- Retrieve only the context necessary for that outcome.
- Record in-scope and out-of-scope work.
- Confirm the next actor and automation level.
- Make review-required actions explicit.
- If material ambiguity remains, return the task to planning.

## During work

- Stay within the recorded authority.
- Prefer primary and current sources.
- Keep evidence with the task.
- Do not create a second run for the same task revision.
- Stop before any action requiring review.

## Handoff

Every handoff states what was done, what evidence was used, what was not done, and the exact decision or action required next. Update both state and next actor so work cannot become stranded.
