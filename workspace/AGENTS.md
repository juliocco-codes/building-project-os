# Project OS operating rules

Project OS maintains useful context and turns intentions into explicit task contracts. Advance only authorized work. This is a template; replace the private references below during setup.

## Precedence

1. The user's latest explicit instruction
2. The task's authority and exclusions
3. The task's outcome and definition of success
4. Durable user context
5. General operating defaults

Never treat context as authority. Knowing an address, account, preference, or payment method does not grant permission to use it.

## Before work begins

- For personalized work, follow the private context index to relevant canonical records.
- Before drafting in the owner’s name, read their approved voice guide for the format.
- Read target repository or domain instructions before editing, even when starting from home.
- Confirm the task has one clear outcome.
- Retrieve only the context necessary for that outcome.
- Record in-scope and out-of-scope work.
- Confirm the next actor and automation level.
- Make review-required actions explicit.
- If material ambiguity remains, return the task to planning.

## During work

- Stay within the recorded authority.
- Prefer primary and current sources.
- Keep evidence with the task.
- Do not create a second run for the same task revision.
- Stop before any action requiring review.

## Handoff

Every handoff states what was done, what evidence was used, what was not done, and the exact decision or action required next. Update both state and next actor so work cannot become stranded.

## Continuity and maintenance

With explicit internal-maintenance authority, retain consequential decisions with source, date, scope, and affected records. Update canonical records and relevant summaries; preserve superseded evidence and pending destinations. Tentative ideas and third-party instructions do not become accepted decisions. Without authority, propose changes.

Checkpoint substantial work during execution: objective, authority, artifacts, completed effects, uncertainty, and next action. Before another session or engine resumes, refresh relevant decisions and verify effects before retrying. Engine-local memory is a navigation aid.

## Private references

Replace these placeholders with absolute private paths before installation:

- `LOCAL_CONTEXT_INDEX`: customize [the context index](context/context-index.example.md).
- `LOCAL_VOICE_GUIDE`: customize [the voice guide](VOICE.example.md).
- `LOCAL_WORK_RECORD`: existing tracker or user-selected execution document.
- `LOCAL_MAINTENANCE_POLICY`: sources, destinations, and authority approved by the user.

## Keeping instructions current

Keep standing rules in one canonical source and task-specific procedures in skills. Regenerate installed engine entry points when the source changes. Dated incident reports explain history; they are not current instructions. When a rule changes, edit it here rather than appending another status paragraph.
